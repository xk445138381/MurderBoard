# MurderBoard UI 设计方向

本文档是给设计审查和开发 agent 的 UI 方向说明。它不定义业务实现细节，只定义 MurderBoard 首版应该呈现的体验、布局、视觉语言和上线审查标准。

## 设计定位

MurderBoard 是桌游玩家在游戏中使用的个人推理案件板。界面应像一个冷静、专业、可长时间使用的调查桌面，而不是通用管理后台、恐怖片海报或营销页面。

关键词：

- 冷静调查桌面。
- 快速记录。
- 关系推理。
- 本地个人工作台。
- 克制悬疑感。

避免：

- 血腥、恐怖、惊悚装饰。
- 大面积红线墙和戏剧化阴影。
- 奶油色卡片后台。
- 大 hero、营销文案和功能介绍页。
- 卡片套卡片的表单堆叠。

## 视觉系统

### 色彩

使用深色工作台承载浅色证据卡，强调色只用于状态和当前焦点。

| 用途 | 建议色值 | 说明 |
| --- | --- | --- |
| App 背景 | `#171411` | 深色调查桌面。 |
| 画布背景 | `#211d18` | 比 App 背景略浅，承载节点。 |
| 纸卡背景 | `#f3ead8` | 人物、线索、事件、猜想节点主体。 |
| 次级纸卡 | `#d9cec0` | 空状态、辅助区域。 |
| 主文字 | `#f7f0e4` | 深色背景文字。 |
| 卡片文字 | `#1f1a15` | 浅色节点文字。 |
| 边框 | `#4a4035` | 工具栏、Inspector、分割线。 |
| 焦点/选中 | `#d6a84f` | 当前选中节点、活动工具。 |
| 支持关系 | `#61c6c1` | `supports`。 |
| 反驳关系 | `#b75a4a` | `refutes`。 |
| 顺序关系 | `#d6a84f` | `sequence`。 |
| 嫌疑关系 | `#c7773d` | `suspect`。 |
| 普通关系 | `#8f877d` | `related`。 |

### 字体和层级

- 使用系统 sans-serif 或现有 Inter 风格，保证桌游现场可读。
- 不使用负字距，不用视口宽度缩放字体。
- 画布节点标题建议 14-16px，辅助信息 12-13px。
- 工具栏和 Inspector 文字保持紧凑，避免大标题占据工作区。

### 形状和边框

- 组件圆角不超过 8px。
- 节点可有轻微纸张质感，但不要使用假贴纸、手绘 SVG 或装饰性噪点。
- 面板边框要清楚，但不能比内容更抢眼。
- 选中态使用边框和细微阴影，不使用大面积发光。

## 主屏布局

主屏是 `Board`。它应填满应用主区域。

布局：

- 顶部命令栏：案件选择、搜索、关系筛选、保存状态、撤销入口。
- 左侧快速录入：人物、线索、事件、猜想四个入口。
- 中间画布：节点和关系线，是视觉重心。
- 右侧 Inspector：编辑当前选中的节点或关系。

比例建议：

- 顶部命令栏高度 48-56px。
- 左侧栏宽度 240-280px。
- 右侧 Inspector 宽度 300-360px。
- 中间画布占剩余空间，不应被卡片容器包住。

平板：

- 左侧快速录入可折叠。
- Inspector 可作为抽屉打开。
- 画布仍是主区域。

手机：

- 保证最低可用：查看、搜索、快速补录。
- 不要求完整自由画布体验。

## 节点设计

四类节点必须一眼可分。

| 节点 | 视觉方向 | 关键信息 |
| --- | --- | --- |
| 人物 | 竖向身份卡，左侧小色条 | 名称、角色、怀疑度或备注摘要。 |
| 线索 | 证据便签，顶部标签 | 标题、来源、发现时间。 |
| 事件 | 时间卡，强调时间字段 | 标题、发生时间、简短描述。 |
| 猜想 | 推理卡，强调状态 | 猜想标题、状态、可信度或待验证标记。 |

节点约束：

- 节点宽度稳定，避免内容变化导致布局跳动。
- 标题最长一行截断或换行两行，不能溢出。
- 节点选中态必须明显。
- 节点悬停应显示可连接、可编辑或可拖动提示。

## 关系设计

关系线必须表达语义。

| 类型 | 颜色 | 线型建议 | 用途 |
| --- | --- | --- | --- |
| `related` | 中性灰 | 细实线 | 普通关联。 |
| `supports` | 冷青 | 实线 | 证据支持猜想。 |
| `refutes` | 暗红 | 实线 | 证据反驳猜想。 |
| `sequence` | 琥珀 | 带方向线 | 时间或发生顺序。 |
| `suspect` | 橙褐 | 强调线 | 人物与嫌疑相关。 |

关系要求：

- 画布必须提供关系图例或筛选控件。
- 关系类型选择应是菜单或分段控制，不应要求用户输入文本。
- 关系过多时，筛选必须能降低视觉噪音。
- 不允许所有关系都显示成同一种红线。

## 快速录入

快速录入是游戏中使用的核心路径。

要求：

- 默认只展示最少字段。
- 人物：名称、角色或备注。
- 线索：标题、来源、内容摘要。
- 事件：标题、发生时间、描述。
- 猜想：标题、当前判断、状态。
- 创建后节点直接出现在画布，并自动选中进入 Inspector。
- 详细信息放到 Inspector，不放在创建入口。

## Inspector

Inspector 编辑当前选中的节点或关系。

要求：

- 空选中时显示简短提示和案件统计。
- 选中节点时编辑节点详情、状态和相关关系。
- 选中关系时编辑关系类型和备注。
- Inspector 不应覆盖画布主区域；平板上可以抽屉形式出现。

## 文案

文案要像玩家工具，不像项目管理软件。

推荐：

- "Add clue"
- "Add hypothesis"
- "Link as support"
- "Refutes this"
- "Find on board"
- "Known so far"

避免：

- "Manage entities"
- "Create record"
- "Perform operation"
- "Action failed" 作为唯一错误标题。
- 大段解释功能价值。

## 开发交接要求

开发 agent 实现前应先对齐：

- `Board` 是默认入口。
- 画布为主，表单为辅。
- 四类节点和五类关系语义不可删减。
- 设计 token 先落地，再实现细节组件。
- 现有 `Cases`、`Entities`、`Evidence`、`Timeline` 是辅助页，不是首版主屏。

## 上线设计 Gate

设计通过必须满足：

- 第一屏明确是案件板。
- 深色工作台和浅色节点形成稳定对比。
- 玩家能快速创建人物、线索、事件和猜想。
- 关系线有清楚语义和筛选入口。
- 搜索能定位画布节点。
- Inspector 可编辑但不压迫画布。
- 桌面和平板截图没有文字溢出、遮挡和错位。

设计不通过包括：

- 主屏仍是列表或长表单。
- 案件板只是页面中的一个小模块。
- 关系线没有语义或全是红线。
- 快速录入字段过多。
- 视觉偏恐怖片、营销页或普通后台。
- 空状态大量解释功能，而不是引导开始建板。
