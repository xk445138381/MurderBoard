# MurderBoard 产品需求说明

MurderBoard 是给桌游玩家个人在游戏中使用的本地优先推理案件板。它帮助玩家快速记录自己已知的人物、线索、事件和猜想，并用可视化关系板在游戏中找回证据链、嫌疑关系和推理矛盾。

首版目标不是通用案件管理系统，也不是主持人工具或创作者写作工具。首版必须服务一个核心问题：玩家在桌游推理过程中，能不能更快记录、关联并找回关键信息。

## 首版用户

### 桌游玩家

玩家在推理桌游、剧本杀或推理 TTRPG 进行中独立使用 MurderBoard。用户只记录自己已经知道的信息、自己的猜想和当前怀疑对象，不保存主持人答案、完整真相或未公开线索。

## 用户目标

- 在游戏进行中快速记录人物、线索、事件和猜想。
- 将人物、线索、事件和猜想放到可视化案件板上。
- 用类型化关系表达支持、反驳、时间顺序、嫌疑和普通关联。
- 在 10 秒内找回关键人物、线索、猜想或关系。
- 持续调整自己的推理，而不会被复杂表单打断游戏节奏。

## 首版范围

- 案件板：作为默认主界面，展示人物、线索、事件、猜想四类节点。
- 快速录入：用最少字段创建人物、线索、事件和猜想。
- 类型化关系：支持 `related`、`supports`、`refutes`、`sequence`、`suspect`。
- 节点布局：保存案件板节点位置，玩家再次打开时保持布局。
- 搜索与定位：按名称、内容、类型和关系快速找到节点。
- Inspector：编辑选中节点或关系，不离开案件板上下文。
- 本地持久化：数据保存在本地 IndexedDB，不要求账号或联网。
- 基础数据维护：保留案件、回收站、归档、导入和复制等能力，但它们不是首版核心体验。

## 暂不包含

- 多人协作、共享房间、账号和权限系统。
- 实时同步编辑。
- 主持人控制台、答案管理或真相揭示流程。
- 自动推理、AI 判断凶手或 AI 生成结论。
- 拍照、附件、OCR 和媒体管理。
- 对外发布、分享页面或公开案件库。
- 复杂导入模板和完整剧本导入。

## 功能需求

### 案件板

- 用户打开应用后应优先进入案件板，而不是列表管理页。
- 案件板应包含顶部命令栏、左侧快速录入区、中间画布和右侧 Inspector。
- 案件板应优先适配平板和笔记本；手机只需保证最低可用的查看和补录。
- 画布是主区域，不应被表单、卡片或说明文案压缩成小组件。

### 节点

- 用户可以创建、编辑、删除人物节点。
- 用户可以创建、编辑、删除线索节点。
- 用户可以创建、编辑、删除事件节点。
- 用户可以创建、编辑、删除猜想节点。
- 节点应有明确类型视觉，玩家在画布上能快速分辨四类节点。
- 删除节点不应破坏历史数据；相关关系应能安全处理缺失节点。

### 猜想

- 猜想是首版核心对象，用于记录玩家当前推理、嫌疑判断或待验证结论。
- 猜想可以关联人物、线索和事件。
- 猜想应支持状态或可信度表达，例如待验证、较可信、被反驳。
- 猜想不得被系统当作事实或答案。

### 类型化关系

- 用户可以在任意同一案件内的核心节点之间建立关系。
- 关系类型限定为：
  - `related`：普通关联。
  - `supports`：证据支持猜想或判断。
  - `refutes`：证据反驳猜想或判断。
  - `sequence`：事件或信息存在时间顺序。
  - `suspect`：人物与嫌疑或猜想有关。
- 关系应可编辑、删除和按类型筛选。
- 关系视觉必须清楚表达语义，不能退化成无含义的自由连线。

### 快速录入

- 创建节点时只要求最少字段。
- 详细信息应在 Inspector 中补充，不应让游戏中录入变成长表单。
- 录入入口应始终靠近案件板，玩家不应为创建线索跳转到远离画布的页面。

### 搜索和定位

- 用户可以搜索人物、线索、事件、猜想和关系。
- 搜索结果应能定位到画布中的对应节点。
- 搜索和筛选必须服务 10 秒找回目标。

### 基础整理能力

- 用户可以创建、重命名和删除案件。
- 删除默认软删除，并保留基础恢复能力。
- 归档、导入、复制和移动属于整理效率功能，不应优先于案件板体验。

## 非功能需求

- 本地优先，无账号和联网依赖。
- 核心操作失败时应给出玩家能理解的错误提示。
- 默认查询不显示软删除内容。
- 节点关系只能连接同一案件内资源。
- 时间字段应可排序、可比较、可序列化。
- UI 在深色背景下必须保持可读性和足够对比度。
- 案件板布局不得在常规编辑、搜索和选择操作中发生意外跳动。

## 设计验收标准

- 第一屏像可视化推理案件板，而不是 CRUD 后台。
- 玩家能在 10 秒内找回关键人物、线索、猜想或关系。
- 快速录入足够短，不打断游戏节奏。
- 四类节点在画布上视觉可区分。
- `supports`、`refutes`、`sequence`、`suspect`、`related` 的关系语义清楚。
- Inspector 可以编辑当前选择对象，但不压迫画布。
- 桌面和平板宽度下节点文字不溢出、不遮挡。
- 空状态引导玩家开始建板，而不是解释大量功能。

## 工程验收标准

- 无法创建重名案件。
- 不能在不同案件资源之间建立关系。
- 猜想可创建、编辑、软删除和恢复。
- 节点位置可保存和恢复。
- 软删除节点后，相关关系查询和画布渲染不会崩溃。
- `npm test`、`npx vitest run src` 和 `npm run build` 通过。
