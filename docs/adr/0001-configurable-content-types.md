# 0001-configurable-content-types

MurderBoard 最初硬编码了 6 种内容实体（Character、Clue、Event、Hypothesis、BoardEntity、EvidenceItem），隐含假设是"所有推理桌游的结构相同"。经过真实游戏对照发现，不同游戏有不同的内容分类和字段需求（如明朝探案的验尸报告 vs 现代刑侦的法医报告），硬编码类型体系无法复用。决定改为**可配置内容类型系统**：玩家在开局时定义类型（名称 + 字段模式 + 板面视觉），工具提供 9 种字段类型池和模板库作为基础设施。代码不再预设任何游戏的内容结构。

**Status**: accepted

**Considered Options**

- **Option A**: 保持硬编码，为一款游戏定制。—— 拒绝，因为用户明确要求工具可适配多款推理桌游，一次性工具没有价值。
- **Option B**: 分支/插件体系，每款游戏写一个模块。—— 拒绝，开发和维护成本高，且无法让玩家自己适配没见过的游戏。
- **Option C** (选择): 可配置类型系统 + 模板库。—— 字段类型池覆盖所有已知需求，模板系统让玩家自己定义并复用类型结构，工具代码不包含任何游戏知识。

**Consequences**

- `src/domain/types.ts` 需要完全重写，现有所有硬编码实体接口将被移除
- 存储层（IndexedDB）需要支持动态 schema 的内容项存储（JSON blob 或等效方案）
- 板面渲染需要根据内容类型定义动态绘制节点视觉（颜色、形状）
- Inspector 面板需要根据字段定义动态生成编辑表单
- 新结构下旧测试数据将不兼容，需要从零重建
