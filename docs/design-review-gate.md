# MurderBoard 设计审查 Gate

本文档用于上线前 UI 和体验审查。开发 agent 完成实现后，应提供本地预览或截图，由设计审查者按本 gate 判断是否可以进入工程上线流程。

## 审查输入

提交审查时必须提供：

- 桌面宽度截图，建议 1440px 或接近尺寸。
- 平板宽度截图，建议 768px 到 1024px。
- 空案件板状态截图。
- 至少一个包含人物、线索、事件、猜想和五类关系的样例案件截图。
- 关键流程说明：创建节点、建立关系、搜索定位、编辑 Inspector。

## 阻断项

出现任一项即不通过：

- 默认第一屏不是案件板。
- 画布不是主视觉，只是列表页或表单页里的小组件。
- 不能在同一页面完成创建节点、建立关系和查看详情。
- 四类节点视觉不可区分。
- 五类关系语义不可区分。
- 节点文字明显溢出、遮挡或压住其他 UI。
- 深色背景下文字、关系线或选中态对比度不足。
- 快速录入是长表单，明显打断游戏节奏。
- 视觉风格偏恐怖片、血腥、营销页或普通 CRUD 后台。

## 评分项

每项 0-2 分，总分 16 分；低于 13 分不建议上线。

| 项目 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 案件板主导性 | 画布弱 | 画布可见但不主导 | 画布明确主导 |
| 临场录入效率 | 字段过重 | 勉强可用 | 快速、短、不中断 |
| 节点识别 | 类型难分 | 需细看 | 一眼可分 |
| 关系语义 | 无语义 | 部分清楚 | 清楚且可筛选 |
| 搜索找回 | 不明显 | 可搜索但定位弱 | 能快速定位 |
| Inspector | 遮挡或缺失 | 可用但拥挤 | 清楚且不压迫画布 |
| 响应式 | 平板明显坏 | 基本可用 | 桌面和平板都稳定 |
| 视觉基调 | 偏离方向 | 大体接近 | 冷静调查桌面成立 |

## 任务流审查

审查者应实际走一遍：

1. 创建一个人物。
2. 创建一个线索。
3. 创建一个事件。
4. 创建一个猜想。
5. 建立 `supports` 关系。
6. 建立 `refutes` 关系。
7. 搜索刚创建的猜想并定位到画布。
8. 在 Inspector 中修改该猜想。

通过标准：

- 全流程不需要离开案件板。
- 没有明显布局跳动。
- 操作结果在画布上立即可见。
- 玩家能理解当前选中的节点或关系。

## 文案审查

文案应服务桌游玩家。

通过：

- 使用 clue、hypothesis、suspect、known、support、refute 等推理语义。
- 空状态引导用户添加第一条线索或猜想。
- 错误文案说明玩家需要怎么修正。

不通过：

- 大量使用 record、entity、operation、CRUD、management 等后台语义。
- 空状态解释产品功能而不是引导下一步。
- 错误文案只有 "Unknown error" 或 "Action failed"。

## 上线结论格式

设计审查输出应使用：

```text
Design gate: Pass / Blocked
Score: X/16
Blocking issues:
- ...
Required fixes:
- ...
Nice-to-have:
- ...
```

只有 `Pass` 才能进入最终上线确认。
